# Forrest's Wallet

家庭虚拟零花钱账本与财商启蒙 App。
只记录数字，不承载、不转移、不托管真实资金。

本文档是当前唯一的产品需求说明（PRD），取代 `830c98d` 版本的 README。
内容来自 2026-09-02 完成的六轮需求访谈，共 70 项决策全部经确认。

> **与旧版 README 的关系**
> 旧版来自更早的一条工作线（含一份已评审的 iOS 原型）。本轮访谈重新推导了产品机制与技术架构，二者有 6 处实质冲突，**一律以本文档为准**；冲突清单见文末[附录 A](#附录-a与旧版-readme-的冲突)。旧版中经得起检验的视觉语言与无障碍规范已并入本文档。

## 1. 产品是什么

Forrest（7 岁）在 iPad 上查看自己现在有多少钱、钱为什么变了、规则是什么、离想买的东西还差多少。
爸爸在 iPhone 上记录全部增加、消费、修正和规则。

这不是儿童银行，不是支付工具，也不是普通的余额追踪器。**它是一本 Forrest 看得懂、并且不会冤枉他的家庭账本。**

### 核心契约：1:1 无条件兑现

App 里的余额与现实中他真实拥有的零花钱 **1:1 对应，家长没有否决权**。App 说他有 87 元，他就真的有 87 元。

- **纯记账，不存在实体现金。** 现金一旦存在就成了第二本账，必然和 App 打架。
- 因此这个账本的**准确性和可用性是产品的生命线**，而不是一项功能指标。

## 2. 三条不可动摇的原则

后面每一个决策都从这三条推出。将来要加功能，先拿它们卡一遍。

### 01 · 账本不会冤枉他
余额永远等于流水之和，谁都算得出来。记录不能删、不能悄悄改。7 岁孩子对不公平的敏感度远超成年人——**账不平一次，这个 App 的权威就没了**，之后讲利息讲信用他都不会当真。

### 02 · 教育来自真实后果
不来自奖励机制。他会因为花掉 15 块而离目标远 15 块，会因为花超了而看到红色的负数。**那次后悔才是这个 App 真正教会他的东西**，不是徽章。

### 03 · 数据活得比 App 久
App 可以只活一年，但他攒下的 400 块不能跟着消失——7 岁的孩子不理解"项目烂尾"，只理解"爸爸说话不算数"。备份和人类可读的表结构**不是功能，是契约的一部分**。

### 派生原则

1. Forrest 看到的是"我现在有多少、为什么变了"，不是账户、转账或练习金额。
2. 确认语言说"已记录"，**绝不说"已转账"**。
3. 儿童与家长是两套信息密度和导航，不是同一套界面换皮肤。
4. 权限由**服务端**强制执行，不依赖客户端代码没写错。
5. 历史不可抹掉。儿童看到"我们把金额改对了"；家长看到原记录、冲正与正确记录的关联链。
6. 余额必须从不可变流水导出，不能靠覆盖金额字段。
7. 教育适时出现，不强迫上课。

## 3. 使用者与设备

| | Forrest | 爸爸 |
|---|---|---|
| 设备 | 自己的 iPad（儿童 Apple ID，家庭共享下） | 自己的 iPhone |

| 词汇量 | 约 800 词，能读字 | — |

## 4. 角色、认证与权限

### 4.1 设备定角色

角色在**配对那一刻由服务器记录**，写入设备行，不是纯本地状态。iPad 永远是儿童视图，iPhone 永远是家长视图。

### 4.2 配对流程

```
① 服务器"首次注册"窗口由运维手动打开一次
② 爸爸的 iPhone 注册 → 获得家长 token（读写）→ 存入 Keychain
③ 注册窗口立即关闭     ← 永远敞开的注册接口等于没有认证
④ 爸爸在家长端点「添加设备」→ 服务器返回 6 位配对码
⑤ Forrest 的 iPad 输入该码 → 获得儿童 token（只读 scope）→ 存入 Keychain
⑥ 此后永不再登录
```

- **配对码**：6 位数字，**10 分钟过期，用一次即作废**。
- **凭据存储**：长期 token 存 Keychain。App 删除 / 重装不丢；免费签名每周重装也不丢。仅在从免费 team 切换到付费 team 时（Team ID 变化）失效一次，重新配对 30 秒即可。
- **重新配对**：家长端永久保留入口，藏在设置里。
- **儿童端不提供任何"退出登录 / 重新配对"入口**——Forrest 没有把自己弄丢的办法。
- **PIN 用途**：仅保护家长端的"预览儿童视图"入口。
- **家长预览**：可随时查看 Forrest 眼里的画面，改文案时尤其有用。

### 4.3 权限强制

**儿童 token 带 scope，`child` 打任何写接口一律返回 403。** 这是服务端强制，不是客户端 UI 层面的只读。理由：1:1 无条件兑现契约下，一笔幽灵入账是要真金白银认账的。

### 4.4 网络边界

公网 + Caddy 自动 TLS + Bearer token。

## 5. 收入模型

零花钱由两部分组成。**收入只分「基础 / 临时」两类**，不另造分类体系。

### 5.1 基础零花钱 · 周考核

条件式，按周结算。示例条件：每周 5 日上学全勤、每日跳绳、每日喝牛奶（内容可调整）。

**计分方式：分项计分 + 全勤奖。**

| | |
|---|---|
| 为什么不是全有全无 | 漏一项就归零，对 7 岁太残酷——周三一失败，周四到周日就没有任何动力了，会教出"反正做不到就摆烂" |
| 为什么不是纯分项 | 缺少"坚持到底"的份量 |
| **分项 + 全勤奖** | 每份努力都算数，不会因一次失败全盘皆输；同时保留坚持到底的额外价值 |

**计分单位是「周」，不是「天」。** 一周只有 3–4 个整数相加——**能自己验算是他信任账本的前提**。

```
本周跳绳（目标 5 次，达成 5 次）  →  +5 元
本周喝牛奶（目标 7 次，达成 6 次）→  +0 元   ← 差一次就不给这一项，规则简单
本周上学全勤                      →  +5 元
三项全达成奖励                    →  未达成
─────────────────────────────────────────
本周基础零花钱                    →  10 元
```

量级：约 10–20 元/周（具体金额待定，见[开放项](#17-开放项)）。

**明确否决自动发钱**（如"每周一自动 +10 元"）：会教出"钱会自己长出来"，与产品目标相反。

### 5.2 临时零花钱 · 一事一议

帮忙做家务、积极做一件特别的事等。事项与金额**当面商量后由家长直接记账**。

**不做"先约定、后兑现"的状态机**：7 岁的时间尺度很短，待办状态活不过几小时，会积压成负债。

### 5.3 本周看板

7 天 × N 项的网格，家长端可勾选，**Forrest 在次级页可查看**（他能随时看到进度，有成就感）。

**格子有三态，不是两态：**

| 状态 | 显示 | 含义 |
|---|---|---|
| ✅ 已完成 | 实心勾 | 做到了，家长记了 |
| ➖ **还没记** | 空心 / 虚线 | **家长还没记这一格** |
| ⬜ 还没到 | 灰色，不可点 | 未来的日子 |

**为什么必须三态**：只有两态时，家长忘了勾的那天，Forrest 看到 ✗——App 在说"你没做到"，而事实是"爸爸没记"。**这是账本在往对他不利的方向说谎。**

- 平时随时可补勾，不强制每日打开。
- **只有到周日结算那一刻，还空着的格子才结算为未达成。** 在那之前文案永远是"还没记"。

### 5.4 规则可编辑与留痕

- 家长可增删改打卡项（名称 / 每周目标次数 / 金额）与全勤奖金额。
- **不做规则版本管理**；改为**结算时把当时的规则名和金额快照进交易记录**，历史永远显示当时的真相。
- **规则变更在儿童端留一条可见记录**（例："从 10 月 1 日起，跳绳从 5 元变成 3 元"）。
  规则是父子商量出来的——**如果它能被单方面、无声地改掉，那"商量"就是假的**。

### 5.5 周日对账仪式

每周日，父子一起：看这周的格子 → 算出这周赚了多少 → 看目标近了多少 → **Forrest 可以提出异议**。

> 平时随时补勾解决的只是"漏记"。周日这 10 分钟是这个 App 唯一的父子对话场景，**全部教育价值都发生在这里**。砍掉它，产品就退化成一个记账工具。

**风险提示（结构性，App 解决不了）**：格子里的"事实"是父子共同商定的，不是客观记录。若有分歧，App 只负责让分歧发生在**周日的桌子上**，而不是超市结账的队伍里。

## 6. 支出

### 6.1 交易字段

金额（分存储 / 整数元显示）· 日期 · 一句话事由（2–8 字）· 方向 · 分类（**选填**）

### 6.2 分类

用他的世界的类别，不是会计科目：

🍦 吃的 ・ 🧸 玩具 ・ 🎮 游戏 ・ 📚 书和文具 ・ 🎁 送人的礼物 ・ ❓ 其他

- **选填**，跳过则默认落"其他"。
- MVP 固定这 6 类，不提供编辑入口；但存成数据表而非硬编码枚举。

### 6.3 录入摩擦

**目标：3 次点击 / 15 秒。**

```
首页「＋ / −」 → 数字键盘 → 确认
                              ↑
                    事由与分类在确认之后，可跳过
```

> **家长的懒惰是这个项目的头号死因。** 任何必填字段都是在给以后偷懒埋雷；偷懒一次，1:1 契约就裂了。这也是"照片放 v2"的唯一原因。

## 7. 账本完整性

### 7.1 不能删，只能冲正

已确认的记录**不可删除、不可破坏性编辑**。记错了就记一笔**反向交易**抵消，**原记录与更正记录都留在流水里**。

1. **账本不可篡改**——否则余额就不再是账本算出来的，而是家长说了算的。
2. **这就是真实会计的做法**，有教育价值：Forrest 看到"记错了 → 用一笔更正来修复"，而不是"错误凭空消失了"。这一课讲信用卡账单时会再用一次。
3. **实现最简单**：不需要编辑逻辑，只要一个"更正这笔"按钮生成反向记录。

代价（接受）：手滑记错，流水里会永远躺着两条。**错误也是账本的一部分。** 若实际使用中太烦，再加"5 分钟内可撤销"窗口，但不一开始就加。

### 7.2 余额来源

余额**永远等于流水之和**，不存独立的余额字段。

### 7.3 负余额：允许

他看中 50 元的东西只有 30 元，家长先垫上——这笔要记。

- 允许余额为负，**显眼标红**，用他的话说明"**你现在欠爸爸 20 元**"。
- 下次进账**优先抵扣**。

**为什么不禁止超支**：禁止看着安全，实际后果是**家长干脆就不记了**，账实不符，契约破裂。而且负余额是"借钱"这一课最自然的入口——**不是我们教他，是他自己撞上的**。他会盯着那个红色的 −20 好几天，那个感受比任何解释都管用。

## 8. 攒钱目标

### 8.1 规格

| 项 | 决定 |
|---|---|
| 数量 | **同时只有一个**。换目标进度清零重来——"换目标"这个动作本身就是取舍教育 |
| 锁不锁钱 | **不锁**。目标只是一条参照线，他随时可以把钱花光 |
| 代价可见 | 每笔支出提示"**离你的目标又远了 X 元**" |
| 预计周数 | **不显示** |
| 设目标护栏 | 预计超过 8 周时温和提示"这个要攒很久哦，要不要先定一个小一点的？" |
| 达成 | 提示"**你可以买了**"，**不自动扣钱**。真买了由家长记一笔支出，目标归档 |
| 归档 | 进入"**已实现的心愿**"列表——他真实的、可回看的成就记录（不是游戏化徽章） |

### 8.2 为什么不锁钱

锁钱把余额分成"能花的"和"存起来的"两个口袋：7 岁难以理解，且**与 1:1 契约冲突**（钱是他的，凭什么锁）。

**可见代价的教育价值高得多**：锁钱教的是"被管着"，可见代价教的是"我自己选的"。选择权完全在他手上，后果清清楚楚摆在眼前——他一定会有几次没忍住、然后后悔，**那次后悔才是真正的一课**。

### 8.3 为什么不显示预计周数

按基础 15 元/周，400 元的目标要攒 **27 周**；加临时零花钱约 10 元/周也要 **16 周 ≈ 4 个月**。**对 7 岁来说 4 个月约等于永远。** 首页天天挂着"还要 16 周"不是激励，是每天提醒他这事没戏。

护栏放在**设目标那一刻**：先让他设一个 2–3 周能达成的小目标，**尝到一次"攒钱成功"的滋味**——第一次成功的体验决定他这辈子对存钱的感觉，不该拿一个 4 个月的目标去赌。

## 9. 界面规格

### 9.1 Forrest · iPad（全部只读）

**首页信息层级（一屏之内）**

1. **我现在有多少钱** —— 超大数字，占上方约 1/3 屏。这是他打开 App 的唯一理由
2. **目标还差多少** —— 进度条 +「已攒 X / 目标 Y」+「还差 Z 元」
3. **最近 5 笔流水** —— 时间轴，图标 + 事由 + 金额，**每行带变动后余额**（他可以自己往回数着验算）

**次级页**

- **本周看板**：三态格子
- **规则清单**：固定规则（基础零花钱条件）与临时规则历史。语言只说明条件、状态、结果和家长确认，**不责备**。临时规则用"总数 + 最近几条 + 查看全部"，避免撑坏界面
- **规则变更记录**
- **全部流水**
- **已实现的心愿**

**信任状态**：在线 / 离线缓存 / 更新失败 / 空账本。离线时明确显示"正在显示已保存的信息"。

**配对欢迎页**：用他能懂的话说明——能看现在有多少、每笔为什么变、规则和目标；爸爸负责记录；**App 不会动银行卡或现金**。

### 9.2 爸爸 · iPhone

- **首页**：Forrest 当前余额 + 增加 / 消费 / 修正入口
- **增加与消费**：金额 → 确认 →（可选）事由、分类、日期 → 服务端成功。成功页写清**没有真实资金移动**
- **修正**：保留原记录，写入冲正，再写入正确替代记录
- **本周看板**：勾选 / 补勾
- **周日结算**：按规则自动算出本周基础零花钱 → 家长确认 → 生成一笔交易
- **规则管理**：增删改打卡项与金额、全勤奖
- **历史与详情**：已确认记录不可破坏性编辑或删除
- **设置**：已配对设备、撤销设备、添加设备（配对码）、PIN、预览儿童视图、隐私说明

**家长离线时不能写入**，必须明确提示"没有写入任何记录"。V1 写入必须联网并等待服务端确认。

## 10. 产品价值观：童趣 vs 游戏化

**判据：每加一个元素就问——它是让 Forrest 更容易看懂真实情况，还是让他更想打开这个 App？前者留下，后者删掉。**

| ✅ 留下 · 童趣 = 降低认知门槛 | ✕ 删掉 · 游戏化 = 劫持动机 |
|---|---|
| 大字号、高对比、大点击区 | 徽章、成就、等级 |
| 具象图标、颜色区分收支 | 连续打卡、连击 |
| 口语化短句（"你现在有 87 元"） | 排行榜、与别人比较 |
| 钱包 / 存钱罐这类朴素比喻 | 虚拟宠物、装扮、解锁皮肤 |
| 时间轴式流水，像绘本翻页 | 庆祝"你打开了 App""连续看了 7 天" |
| **收到钱时的庆祝动画与音效** | **儿童端的任何推送通知** |

### 两条精确边界

1. **庆祝只能绑「真实事件」，不能绑「使用行为」。** 钱确实来了，值得高兴；打开 App 不值得。
   细化：**只有收入庆祝**。消费、负余额、修正一律用一次安静反馈，不做庆祝。开启"减弱动态效果"时改为静态反馈。
2. **"永不推送"只约束儿童端。** 给家长端发周日结算提醒完全合理——那是成年人自己要的工具提醒。**Forrest 的 iPad 上一条通知都不会有。**

## 11. 视觉与语言

方向是**自然观察手账，不是儿童银行**。沉静植物色、结实圆体字、线描与纸片插画、直接动词。
不使用吉祥物、仿真信用卡、霓虹游戏化或金融机构式界面。

| 用途 | 色值 |
|---|---|
| 云杉墨绿 | `#173D35` |
| 新叶绿 | `#D8EDD5` |
| 零花钱暖黄 | `#F3C968` |
| 手账纸白 | `#FBF7ED` |

- 标题 SF Pro Rounded / `ui-rounded`；正文 SF Pro Text / 苹方
- 儿童卡片圆角约 24pt，家长卡片约 16–20pt
- 图标始终配文字
- 儿童大字只说："你现在有" · "加进来了" · "花在" · "已改正" · "还差"

### 无障碍底线

- 最小触控目标 44×44pt，实际做到 48–54pt
- 兼容动态字体；文字卡片不用固定高度
- 增加 / 减少 / 修正**不只靠红绿色**区分
- 进度同时写出 `¥18 / ¥30`，不只靠进度条
- VoiceOver 先说金额和含义，再提供操作
- iPad 常规横屏可用侧栏；半屏 / 紧凑宽度改为底部导航 + 单栏，不整体缩小

## 12. 技术架构

一台服务器，一个写入者，几乎零并发。**任何"正经框架"在这里都是纯负担。**

```
爸爸 iPhone ──HTTPS+Bearer──┐
                            ├──> Caddy(自动TLS) ──> TypeScript API ──> Postgres
Forrest iPad ─HTTPS+Bearer──┘         [Hetzner CAX11 · 约 €3.8/月]        │
        │                                                                 │
        └── 本地 JSON 缓存（离线也能看余额）              每日 pg_dump ────┤
                                                                          ├─> 加密推送到私有 Git 仓库
                                                                          └─> 每周拉回爸爸的 Mac
```

| 层 | 选择 | 理由 |
|---|---|---|
| 机器层 | **OpenTofu**（50 行封顶） | 只写服务器 + 防火墙 + DNS 三个资源。选 OpenTofu 而非 Terraform 是因为它支持 **state 加密**，加密后可与代码一起进 git。**超过 50 行说明在给基础设施镀金，而 Forrest 还没拿到他的 App** |
| 服务层 | **Docker Compose** | 一个打开就能看懂的 YAML。**能看懂 > 理论最优** |
| 反代 / TLS | **Caddy** | 三行搞定自动续期，无人值守也不会坏 |
| 后端 | **TypeScript**，无框架、无 ORM | 时间尺度是 1 年 + 高频迭代，优先"先做出来" |
| 数据库 | **Postgres** | `pg_dump` + 标准 SQL 是最通用的数据格式 |
| iOS | **SwiftUI** + Codable JSON 本地缓存 | 缓存需求只是"离线看到上次的数据"，不上 SwiftData（大依赖 + 迁移麻烦） |
| 部署 | `deploy.sh` → GitHub Actions | 先手动，第一次要亲眼看到每一步；成功后立刻升级到自动 |
| 域名 | 新买，DNS 托管 Hetzner | Let's Encrypt 不给裸 IP 发证。服务器 + 防火墙 + 解析同一个 provider |
| 周定义 | 周一 00:00 – 周日 23:59 | 周日晚上结算 |

**环境**：Xcode 26.6 / Swift 6.3.3 / iOS 26.5 模拟器 / Node v24.16.0。

### 12.1 数据模型要点

- **表结构必须人类直接读得懂**：一张 `transactions` 表，**不要事件溯源、不要 JSON 大字段**。这样哪天 App 停用，打开备份文件还能给 Forrest 一个交代。
- 交易可归属不同账户类型（现金 / 储蓄 / 负债）——MVP 只用其一，后面加储蓄罐、借条、信用卡是**加类型和规则，不是推翻重来**。
- 结算生成的交易需冗余存下**当时的规则名与金额**。

### 12.2 备份：全场最重要的一环

数据量小得离谱——一天 5 笔 × 365 天 × 10 年 ≈ 1.8 万行，**撑死 10 MB**。所以备份可以做得很奢侈而成本为零：

1. 服务器本地每日 `pg_dump`，保留 30 天
2. 加密后推到**私有 Git 仓库**（白送版本历史 + 异地存储，€0）
3. Mac 上 launchd 每周拉一份回来

**最关键的一条：`restore-test.sh`。没有验证过的备份等于没有备份。** 每月自动把最新备份恢复到临时库并对比行数，失败即告警。这是运维里最经典的坑。

### 12.3 监控

**healthchecks.io** 的 dead man's switch：服务器每天 ping 一次，超时没 ping 到就发邮件。五分钟配好——否则服务器挂了可能几天不知道（Forrest 那边有本地缓存，不会立刻暴露）。

### 12.4 成本

| 项 | 费用 |
|---|---|
| Hetzner CAX11（2 vCPU / 4 GB） | ~€3.8/月 |
| 域名 | ~€12/年 |
| 备份（私有 Git + Mac） | €0 |
| healthchecks.io | €0 |
| **合计** | **约 €5/月** |

## 13. 必须成立的故事

1. **零花钱到账**：家长记录 +¥10 → 服务端确认 → Forrest 看到新余额和原因，附一次庆祝反馈。
2. **一次消费讲得明白**：家长记录购买 → Forrest 打开详情 → 用途、日期，以及"之前 − 消费 = 之后"。
3. **错误被修正，而不是被藏起来**：误记 ¥14 → 冲正 + 正确记录 → 结果 ¥11，双端都看得到关联链。
4. **周日结算**：父子一起过看板 → 三项达成两项 → App 算出 10 元 → 家长确认 → 入账。**Forrest 能自己把 5 + 5 算出来并验证。**
5. **格子空着不等于失败**：周三 Forrest 打开看板，周三那格显示"还没记"而不是叉号；周日一起补勾后变成 ✅。
6. **目标够得着**：Forrest 看到"已攒 87 / 400 元，还差 313 元"。没有倒计时、连续打卡或消费诱导。
7. **花钱是有代价的**：记录一笔 ¥15 消费后，界面告诉他"离你的目标又远了 15 元"。
8. **欠钱**：花超之后余额变成 −¥20，红色显示"你现在欠爸爸 20 元"；下次零花钱先抵扣。
9. **规则改了他知道**：金额从 5 元调到 3 元，Forrest 的规则页出现一条变更记录。
10. **离线可读**：服务器不可用时，Forrest 打开 App 仍能看到上次的余额，并标明"正在显示已保存的信息"。

## 14. MVP 边界

### 包含

记账 · 余额 · 流水 · 冲正 · 负余额 · 攒钱目标 · 打卡看板 · 周日结算 · 规则管理与变更留痕 · 设备配对 · 儿童只读视图 · 离线读缓存

### 明确不做

| 不做 | 原因 |
|---|---|
| 真实资金：卡、银行、转账、托管、投资、真实信用评分 | 产品定位 |
| 储蓄利息、借款额度、还款计划、模拟账单、信用评级 | 属于后续教育阶段（见 §15） |
| 儿童端发起任何请求（提款申请、购买请求、自己打卡） | 7 岁，面对面沟通更直接。MVP 保持严格只读 |
| "先约定、后兑现"状态机 | 7 岁的时间尺度很短，待办活不过几小时 |
| 交易照片 | 增加录入摩擦 → 偷懒 → 漏记 → 账不平 |
| 多个攒钱目标 / 锁定储蓄金额 | 见 §8 |
| App 内导出 CSV | 家长有服务器权限；`pg_dump` 已满足"不被厂商锁定" |
| 分类编辑界面 | MVP 固定 6 类 |
| 家长离线写入、冲突合并、发件箱 | 单写入者，不需要 |
| 共同家长、多名儿童 | 不作为上线条件 |
| **儿童端推送通知** | 见 §10 |
| 上架 App Store | 家庭自用 |

### "退出方案"

"一页 Forrest 看得懂的完整账单" **MVP 不做，但表结构现在就要设计对**——真到那天，凭一张干净的 `transactions` 表半小时就能生成。

## 15. 教育概念的解锁顺序

一次只上一个。**每个概念等 Forrest 真正吃透了、并且在现实中撞过一次墙，再解锁下一个。**

| 阶段 | 概念 | 教什么 | 状态 |
|---|---|---|---|
| 1 | 余额与流水 | 钱从哪来、到哪去 | **MVP** |
| 2 | 储蓄罐 + 利息 | 延迟满足有回报 | 后续 |
| 3 | 借钱与还款 | 提前消费有代价 | 后续（入口已埋好：负余额） |
| 4 | 信用额度 | 守信用换来更多自由 | 后续 |

**关于利息**：他的零花钱量级下，任何真实利率都产生不了肉眼可见的数字。届时必须使用**夸张的教育利率**（如每周结算、比例明显），并在界面上**诚实地告诉他**"真实世界的银行给得少很多，我们这里调快了让你看得见"。

**关于信用额度**：形态是"我信任你到 10 元——这 10 元以内你自己记账不用批准；用好了额度提升"。这比任何解释都更能让他理解信用是什么。

## 16. 交付与验收

- **交付方式**：一次做完，不分里程碑。
- **投入**：约 5–6 小时/周。
- **验收标准**：**父子连续用满 3 周，期间没有一次退回笔记本或口算。** 功能多少不重要，这条过了才叫成功。
- **上线节奏**：先自己单机跑满一周、确认账不会乱，**再郑重地给 Forrest 装上**。这个 App 卖的是信任，第一印象只有一次。
- **分发方式**：暂缓决定（免费 sideload / 付费开发者账号 + TestFlight / 付费 + 直接 sideload）。**不阻塞任何架构决策**——所有已选方案都能跑在免费 Personal Team 上。

### 头号风险

**家长的懒惰。** 这个项目最大的风险从来不是技术。1:1 契约要求**每一笔都记、及时记**——漏记一笔，Forrest 就会失去信任。"3 次点击 / 15 秒""任何字段都不必填""照片放 v2"这些决定的唯一动机都是它。

**缓解措施**：先自己单机跑满一周。如果那一周就懒得记了，该停下来重新想，而不是继续往下写。

## 附录 B：被否决的技术方案

记录在此是为了**以后不要重新提出**。

| 方案 | 否决理由 |
|---|---|
| **Sign in with Apple** | **对 13 岁以下账号是硬性封锁，不是流程麻烦。** Apple 官方文档：*"Sign in with Apple is not available for children under 13 years old."*（[support.apple.com/en-us/102609](https://support.apple.com/en-us/102609)）；Apple 员工论坛回复 *"U13 accounts are not supported at this time"*（[forums/thread/134264](https://developer.apple.com/forums/thread/134264)，2020 年至今无变化）。根因是 SIWA 要求账号完成 2FA，而家庭共享下的 U13 儿童账号无法完整设置 2FA。**Forrest 7 岁 → 这条路走不通，与花不花 $99 无关。** 另：SIWA 的 capability 仅对付费开发者账号开放（`APPLE_ID_AUTH` 的 `validTeamTypes` = `["APPLE_DEVELOPER_PROGRAM"]`） |
| CloudKit + CKShare | 私有数据库**按 iCloud 账号严格隔离**，"同一个家庭"在 CloudKit 眼里毫无意义；儿童账号能否稳定接受 CKShare **查不到任何权威结论**——说明基本没人走过；数据可移植性最差 |
| Supabase | 倾向自持，数据主权 |
| Go 后端 | 基于"十年"的论证。前提改为"1 年 + 不断变化"后论证不成立 |
| SQLite | 更省事，但 `pg_dump` + 标准 SQL 在"数据可移植"上更通用 |
| Tailscale / WireGuard | 不是安全性问题（VPN 更安全），是**依赖数量**——会把"Forrest 能不能看到余额"挂在他 iPad 上另一个 App 的运行状态上 |
| 编译期内置 token（双 build scheme） | 免费签名一年要重装约 50 次 = 50 次选错 scheme 的机会，而选错是**静默失败**：Forrest 的 iPad 装成家长版，拿到记账权限且无任何提示。配对码方案只有一个 build，物理上装不错 |
| 用户名密码登录 | Forrest 要记密码；且要认证的是两台设备，不是两个用户 |
| Coolify / Dokploy | 配置存在它自己的数据库里而非 git 仓库，基础设施又变回"点出来的"，与声明式诉求相冲 |
| NixOS | 最彻底的声明式，但学习曲线会在某个没空的月份把人劝退。**能看懂 > 理论最优** |
